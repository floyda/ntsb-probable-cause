# S3.1 — The agent loop: implementation plan

**Spec:** docs/specs/2026-09-30-s3-agent-loop-design.md

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tick a step in the same commit as its code (decision 0017). Log every departure from this plan in the **Deviations** section at the end. Tasks marked **Controller** are run by the controller session, not a subagent: they spend money or need Andy.

**Goal:** Build arm C — the agent loop of the S3 specification (§4–§8) — as the library package `ntsb_probable_cause.agent`, with native tool calling, a batch-round driver, arm B's tool post-pass, S3's sealed sample and statistics file, the `probe` spend kind and S3's spend line; then measure the loop's noise floor on `dev-400`, run registered tuning rounds, and meet the format gate. S3.1 makes no claim (spec §10.5).

**Architecture:** One new package, `src/ntsb_probable_cause/agent/`, that imports the library and is imported by nothing in it except `apps/eval`. A case is a **state machine** (`CaseLoop`): it hands out its next model call and accepts the reply, so the same object is driven synchronously (one `ModelClient.complete` at a time) or in **batch rounds** (every unfinished case's next call in one batch). Evidence reaches the model only as `Payload.from_evidence(split_record(...))` (0016): the first user message is the non-docket evidence, the listing and each document read arrive as the `Payload` of a tool result. Non-evidence tool text (menus of numbers, codes, labels, counts) travels as a new `ToolText` in a tool result, built only by the agent's tools and texts, and every request is checked by the boundary test. Arm C writes the same `RunRecord` / `CaseResult` files as arms A and B, plus `trail.jsonl`, so `ntsb-eval report --against` compares it unchanged.

**Tech Stack:** Python 3.14, uv + hatchling, pydantic v2, httpx, pytest + pytest-socket + respx, ruff, mypy --strict, import-linter, grimp. No new dependency.

## The flow for one trigger (what Task 8 builds)

The conversation for one case is append-only (spec §5.3). Index `n` counts model calls.

- **System text** (identical for every case of a run): `texts.system_text(tables, guidance)` = `prompt.SYSTEM_ANSWER` + `prompt.tables_block(tables)` + `prompt.guidance_block(guidance)` + `texts.PROTOCOL`.
- **Tools** (identical on every call): `schemas.TOOL_DEFINITIONS`, `parallel_tool_calls=False`.
- **User message**: `documents.evidence_payload(raw, exclusions)` — the record without its `docket` key, split with `exclusions`.

| step | `tool_choice` | the reply must call | the tool result sent back |
|---|---|---|---|
| H0 | force `record_hypothesis` | `record_hypothesis` | if documents are offered: `Payload` = listing only, `ToolText` = `texts.menu(offered, not_readable)` + `texts.CHOOSE`; else `ToolText` = `texts.NO_DOCUMENTS` + `texts.CODE_NOW` (skip to coding) |
| choice 1 | force `choose_documents` | `choose_documents` with one decision per offered document | `Payload` = the chosen documents only (if any) + `ToolText` = `texts.read_summary(read, skipped)` + (`texts.RECORD_NOW` if any read, else the second-look menu or `texts.CODE_NOW`) |
| H1 (only if choice 1 read something) | force `record_hypothesis` | `record_hypothesis` | if documents remain: `ToolText` = menu of the rest + `texts.CHOOSE_AGAIN`; else `texts.CODE_NOW` |
| choice 2 (only if documents remain) | force `choose_documents` | as choice 1, over the rest | as choice 1 |
| H2 (only if choice 2 read something) | force `record_hypothesis` | `record_hypothesis` | `ToolText` = `texts.CODE_NOW` |
| coding, up to 6 calls | `"required"` | one of `describe_codes`, `occurrence_usage`, `past_findings`, `suggest_codes`, `submit_answer` | the tool's `ToolText`; after the 6th coding call the next call forces `submit_answer` |
| answer | force `submit_answer` (or chosen during coding) | `submit_answer` | none: the conversation ends |
| refinement | none (json_schema) | — | exactly the runner's stage 2: `system = prompt.SYSTEM_REFINE + prompt.refine_message(answer, tables)`, `history = (Turn(role="assistant", content=<answer JSON>),)`, `REFINEMENT_SCHEMA`; skipped when the answer abstains or has no findings |

**Replies that break the protocol.** A reply with no tool call, a call to a tool the step does not allow, arguments that fail to parse, or a `choose_documents` that misses or repeats an offered document: the loop answers the call with `ToolText("That call was not accepted: {error}")` (a tool result is still owed for every call id) and re-issues the step once; a second failure ends the case `failed: <step>`. Extra tool calls in one reply are each answered with `texts.ONE_CALL` and not run. A coding-tool argument error (unknown code) is not a protocol break: the tool's own text says so, and it counts in `argument_errors`.

**Stops.** `done` (answer submitted), `cap` (the next call's estimate plus the answer reserve would pass the case cap: the coding step stops and `submit_answer` is forced; if even that does not fit, `cap`), `failed: <step>`, `failed: leak`.
