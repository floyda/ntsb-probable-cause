**Goal:** Step 3 of §21: the trail view (§6) at `/case/<case number>/trail/` for every coded case. It shows the agent's beliefs as the spine, the read choices and coding lookups between them, cost beside each step and the total at the top, and the NTSB's verdict last, with a line saying which belief came closest. It's built from the `trail` part of S4's `board/1` export and linked from the opened case. Nothing new is published.

**Architecture:** The same pattern as step 2. Pure functions in `site/src/lib/trail.ts` turn a `CaseFile` into an ordered list of steps and their words, tested with Vitest against the seven sample cases. An Astro component lays them out, and a page builds one trail per case that has a trail. The opened case gains a link to its trail, now that the page exists (the step 2 rule: never link to a page not built yet).

**Tech Stack:** as step 2; no new dependency.

## Global Constraints

- **Step 1 and 2 constraints hold:** branch `s5-public-site`; launch is Andy's decision; inputs are the export only; no inline script or style; WCAG 2.2 AA in light, dark and phone width; `make check` green at every commit.
- **Beliefs are the spine** (§6). Each belief block shows its first code, its cause statement at that point, its confidence, and whether its first code changed from the belief before. It never shows the explanation written for a non-expert (§12 item 4; the export does not carry it).
- **The agent's account of the evidence** (`belief.account`, S4's addition) is shown under each belief in a closed `<details>`, labelled "Ellery's account of the evidence at this point". It is closed by default and needs no script. This is Claude's proposal, and Andy rules on it at the preview (Task 4).
- **Confidence is shown plainly, as fitted, with no claim drawn from it** (§6): "confidence 0.62", two decimals. No bar, no colour, nothing that reads as a score.
- **A document's note is labelled "the agent's note", never "prediction"** (§6, S3.2 result 4). A test checks that no trail page contains "predict".
- **Cost:** each step shows its own cost to four decimals ("$0.0038"), and the total is at the top (§6). The cost is the export's figure, never summed or recomputed by the site.
- **Plain words for tools and decisions,** with the NTSB or system term second in small type where one exists (§12 item 4).
- **No trail page for a case without a trail** (not coded). No link to one either.

## Review Focus

1. **A case with fewer beliefs than read choices** (sample case 2: one read choice that read two documents, then the answer, with no belief in between): the steps must come in true order and never invent a missing belief. Pinned by Task 1's ordering tests.
2. **An awaiting case** (no verdict): the verdict section must say the NTSB has not published, and the closest-belief line is left out, never "no belief matched". Pinned by Task 1.
3. **A long free-text lookup argument, or many documents, on a phone:** no sideways scroll. Pinned by the phone-width check, which already covers every built page.
4. **Floating-point noise in confidence** (`0.45000000000000007`) must print "0.45". Pinned by Task 1.
5. **A document with no page count** (an older export): its line leaves the count out, and never prints "null pages". Pinned by Task 1.

## Task 1: The trail's steps and words

**Files:** Create `site/src/lib/trail.ts`, `site/src/lib/trail.test.ts`.

**Interfaces — Produces:**

```ts
export type TrailStep =
    | { kind: "belief"; belief: Belief; name: string; changed: string | null }
    | { kind: "read"; choice: ReadChoice; name: string }
    | { kind: "lookups"; lookups: Lookup[]; cost_usd: number };
export function trailSteps(c: CaseFile): TrailStep[];              // [] when c.trail is null
export function beliefName(kind: Belief["kind"]): string;          // h0 "Before reading", h1 "After the first read choice", h2 "After the second read choice", answer "The answer"
export function confidenceLabel(x: number): string;                // "confidence 0.45"
export function costLabel(usd: number): string;                    // "$0.0038"
export function documentLine(d: DocumentChoice): { decision: string; detail: string | null };
export function lookupName(tool: string): string;                  // describe_codes "Looked up what codes cover", occurrence_usage "Looked up how often codes come first", past_findings "Looked up findings in past cases", suggest_codes "Asked for suggested codes"; any other tool: its name with underscores as spaces
export function closestLine(c: CaseFile): string | null;           // null when there is no verdict or no trail
```

Ordering rule for `trailSteps`: `h0`; then each read choice in step order, each followed by the belief it led to if the export has one (`choice1` → `h1`, `choice2` → `h2`); then one `lookups` step if there are lookups (its cost is the sum of the lookups' own `cost_usd`, the export's figures added, never repriced); then `answer`. `changed` is `"first code changed"` or `"first code unchanged"` for every belief after `h0`, and null for `h0`.

`documentLine` decisions: `read` → "read"; `skipped` → "skipped"; `scan_only` → "scan only" with detail "no text to read"; `not_offered` by reason: `already_read` → "already read" (detail "at the first read choice"), `photo_only` → "not offered" ("photographs only"), `not_pdf` → "not offered" ("not a PDF"), `fetch_failed` → "not offered" ("could not be fetched"), `over_size_limit` → "not offered" ("over the size limit"), null → "not offered". Pages, when known, are added to the detail: "12 pages" or "1 page".

`closestLine`: the earliest belief whose first code is the NTSB's first code gives "Closest to the NTSB: {beliefName lower-cased}, the first belief to put “{event}” first." If none did: "No belief put the NTSB's first code, “{event}”, first." Event names come from `eventOf`.

- [x] **Step 1: Write the failing tests** — `site/src/lib/trail.test.ts`, against the sample:

```ts
import { readFileSync } from "node:fs";
import { join } from "node:path";
import { describe, expect, it } from "vitest";
import type { CaseFile } from "./board-case-types";
import { closestLine, confidenceLabel, costLabel, documentLine, lookupName, trailSteps } from "./trail";

const SAMPLE = join(__dirname, "../../../tests/fixtures/board");
const kase = (n: number): CaseFile =>
    JSON.parse(readFileSync(join(SAMPLE, `cases/XXX26XX00${String(n)}.json`), "utf8")) as CaseFile;
const shape = (c: CaseFile): string[] =>
    trailSteps(c).map((s) => (s.kind === "belief" ? s.belief.kind : s.kind === "read" ? s.choice.step : "lookups"));

describe("the order of the steps", () => {
    it("interleaves beliefs and read choices (case 1: two reads, each followed by a belief)", () => {
        expect(shape(kase(1))).toEqual(["h0", "choice1", "h1", "choice2", "h2", "lookups", "answer"]);
    });
    it("never invents a belief the export lacks (case 2: a read with no belief after it)", () => {
        expect(shape(kase(2))).toEqual(["h0", "choice1", "lookups", "answer"]);
    });
    it("has no steps for a case without a trail", () => {
        expect(trailSteps(kase(5))).toEqual([]);
    });
    it("marks change from the belief before, and nothing on the first", () => {
        const beliefs = trailSteps(kase(1)).filter((s) => s.kind === "belief");
        expect(beliefs.map((s) => (s.kind === "belief" ? s.changed : "x"))).toEqual([
            null, "first code changed", "first code unchanged", "first code unchanged",
        ]);
    });
    it("costs the lookups step from the export's own figures", () => {
        const step = trailSteps(kase(1)).find((s) => s.kind === "lookups");
        expect(step?.kind === "lookups" ? costLabel(step.cost_usd) : "").toBe("$0.0050");
    });
});

describe("the words", () => {
    it("prints confidence plainly, without float noise", () => {
        expect(confidenceLabel(0.45000000000000007)).toBe("confidence 0.45");
        expect(confidenceLabel(0.62)).toBe("confidence 0.62");
    });
    it("prints cost to four decimals", () => {
        expect(costLabel(0.0038)).toBe("$0.0038");
        expect(costLabel(0.0322)).toBe("$0.0322");
    });
    it("names each document's fate, with pages when known", () => {
        const base = { position: 1, title: "x", note: null };
        expect(documentLine({ ...base, decision: "read", pages: 12, not_offered_reason: null })).toEqual({ decision: "read", detail: "12 pages" });
        expect(documentLine({ ...base, decision: "scan_only", pages: 1, not_offered_reason: null })).toEqual({ decision: "scan only", detail: "no text to read · 1 page" });
        expect(documentLine({ ...base, decision: "not_offered", pages: 9, not_offered_reason: "photo_only" })).toEqual({ decision: "not offered", detail: "photographs only · 9 pages" });
        expect(documentLine({ ...base, decision: "not_offered", pages: 4, not_offered_reason: "already_read" })).toEqual({ decision: "already read", detail: "at the first read choice · 4 pages" });
        expect(documentLine({ ...base, decision: "skipped", pages: null, not_offered_reason: null })).toEqual({ decision: "skipped", detail: null });
    });
    it("names the tools in plain words", () => {
        expect(lookupName("occurrence_usage")).toBe("Looked up how often codes come first");
        expect(lookupName("new_tool")).toBe("new tool");
    });
});

describe("the closest belief", () => {
    it("names the first belief to match the NTSB's first code (case 1: after the first read)", () => {
        expect(closestLine(kase(1))).toBe("Closest to the NTSB: after the first read choice, the first belief to put “Aerodynamic stall/spin” first.");
    });
    it("says so when no belief matched (case 3)", () => {
        expect(closestLine(kase(3))).toBe("No belief put the NTSB's first code, “Fuel exhaustion”, first.");
    });
    it("is left out while the NTSB has not published (case 6)", () => {
        expect(closestLine(kase(6))).toBeNull();
    });
});
```
