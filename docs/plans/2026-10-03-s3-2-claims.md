**Spec:** docs/specs/2026-10-03-s3-2-claims-design.md

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tick a step in the same commit as its code (decision 0017). Log every departure from this plan in the **Deviations** section at the end. Tasks marked **Controller** are run by the controller session, not a subagent: they spend money, touch held-out, or need Andy.

**Goal:** Make S3's claims (spec §1): fix the plumbing a once-only held-out run depends on, without changing a byte the model sees; build the scoring that turns the five runs into a verdict by rules fixed in advance; commit the registration; then run the `dev-400` coding ablation and the four held-out arms once, and publish what they say.

**Architecture:** Two new pure library modules carry every rule the registration fixes: `scoring/claims.py` (the failure rule, the paired difference, beats/matches/worse/undecided, the cost band, "warranted", the headline sentence, the billed figure and the saving split) and `scoring/calibration.py` (the logistic fit, the three-group test, the abstain cut-off). Thin scripts under `scripts/` read run folders and print committed results files through them. The plumbing fixes sit only in files outside the prompt fingerprint (`agent/drive.py`, `agent/run.py`, `scoring/checkpass.py`, `scoring/samples.py`, `apps/eval/__main__.py`); a test holds the loop's prompt version fixed. Paid runs are Andy's, through `scripts/paid_run.sh` in a separate clean checkout.

**Tech Stack:** Python 3.14, uv + hatchling, pydantic v2, pytest + pytest-socket, ruff, mypy --strict, import-linter. No new dependency (the logistic fit is plain Python; there is no numpy in the project).

## Task 3: The resume fixes in `agent/drive.py`

**Files:** modify `src/ntsb_probable_cause/agent/drive.py` (not fingerprinted), `tests/test_agent_drive.py`.

**Background.** `drive_batch` resumes an open round by replaying the replies on disk, then waiting on the recorded batch and taking the replies still missing (`_remaining`, `_take`). Two known issues (S3 spec, "Known issues carried to S3.2"):
1. **All replies on disk, batch reported `cancelled`:** `_remaining` returns no call, but the `cancelled` branch raises `BatchCancelledError` anyway, so the run stops; a second resume continues.
2. **Partly answered, then no result for the rest:** `_is_dead(status)` asks whether the batch returned *any* result. A resumed batch's results include the replies already on disk, so a batch that holds nothing for the *remaining* calls is not seen as dead, and `_take` gives each remaining call a failed attempt (one of its case's two) instead of sending it again.

Use superpowers:systematic-debugging: write the failing test for each issue first, confirm it fails for the reason above, then fix.

- [ ] **Failing test 1** in `TestResume`: a folder with an open round of two calls, both replies written to `replies.jsonl`, no finishing row; the fake batch's `wait` returns `status="cancelled"` with both results. Resume with `drive_batch`. Expected: no `BatchCancelledError`; `rounds.jsonl`'s last row for that round has `status="cancelled"` and its `reported_cost_usd`; the run continues to the next round and finishes. Run it: FAIL with `BatchCancelledError`.
- [ ] **Failing test 2** in `TestResume`: an open round of three calls (cases A, B, C), the reply for A on disk; the fake batch's `wait` returns `status="completed"` with a result for A only (or `status="expired"` with A's result only). Resume. Expected: B's and C's loops are **not** given a failed call (their `call_index` is unchanged after the round); the round is finished with the batch's status and cost; the next round submits exactly B's and C's calls with the same custom ids; after it answers them, both cases finish with no `failed:` reason. - [ ] **Fix** in `drive_batch`, after `_refuse_foreign_results(row, status)` and before the `cancelled` branch:

  ```python
  def fit(stated: Sequence[float], right: Sequence[bool]) -> Curve:
      if len(stated) != len(right) or not stated:
          raise ValueError("stated and right must be the same, non-zero length")
      if all(right) or not any(right):
          raise ValueError("a logistic curve needs both right and wrong answers")
      a = b = 0.0
      for _ in range(100):
          g0 = g1 = h00 = h01 = h11 = 0.0
          for x, y in zip(stated, right, strict=True):
              p = 1.0 / (1.0 + math.exp(-(a + b * x)))
              w = p * (1.0 - p)
              g0 += float(y) - p
              g1 += (float(y) - p) * x
              h00 += w
              h01 += w * x
              h11 += w * x * x
          det = h00 * h11 - h01 * h01
          if det <= 0.0:
              raise ValueError("the fit is singular: every stated confidence is the same")
          da = (h11 * g0 - h01 * g1) / det
          db = (h00 * g1 - h01 * g0) / det
          a, b = a + da, b + db
          if abs(da) < 1e-12 and abs(db) < 1e-12:
              return Curve(a, b)
      raise ValueError("the fit did not converge in 100 steps")
  ```
