Every number on the site gets an entry there: what it measures, its sample, its model, its run and commit, its script, its results file, its interval and the cases it rests on. ## Global Constraints

- **The step 1–4b constraints hold.** Every number comes from the numbers file by key. Every paired figure carries its cases. Every worded claim is a guard in `lib/claims.ts`. Billed costs only.
- **Every entry appears on Methods exactly once**, with an anchor made from its key (`ladder.loop.top1` → `#n-ladder-loop-top1`). A test fails when an entry has no anchor, or when a link anywhere on the site points to an anchor that does not exist.
- **Development, held-out and live never share a figure** (§9, decision 0021). Each entry row names its sample. The board's counts (live) and the evaluation numbers sit in different sections.
- **Numbers come from committed files.** The numbers script refuses a results file with uncommitted changes, so every entry's "recorded in" commit is real. (This changes the order of work: a results file is committed before the numbers file is regenerated, as step 4b already did.)
- **The split diagram is drawn without script** (CSP: no inline script or style). It is a vertical column of boxes and arrows in HTML and CSS, so it fits a phone, and a screen reader reads it as an ordered list. It draws the real mechanism of decisions 0013, 0016 and 0077; each of the guard's five checks is worded from 0016 and `records/split.py`, not from memory.
- **No victim names, clinical tone** (rule 6). Methods quotes no case text.
- **Plain words first.** Each section opens with one or two sentences a non-expert can follow, then the detail. The glossary holds the NTSB terms the other pages show in small type (§12 item 4).

## Review Focus

1. **Completeness:** every entry in `numbers.json` has exactly one Methods row, and every row's sample, model, run, script and results file match the numbers file.
2. **Links:** every `/methods/#…` link on every built page resolves; every GitHub link points to a path that exists at the named commit, or on `main` for a file.
3. **The predictions are the registration's words**, unedited, and each "met / not met" is the claims file's.
4. **The guard's five checks** are described as the code does them, and the diagram's three routes match `split_record`'s three parts.
5. **No sentence mixes development and held-out numbers.**

## Glossary

- **Entry:** one number in the numbers file, with its value, interval, cases, sample, model, run, script and results file.
- **Anchor:** a named place on a page that a link can land on, written after `#` in the address.
- **Recorded in:** the commit that last changed a results file; on GitHub it shows the file as it was when the number was taken from it.
- **Run commit:** the commit whose code produced a model run's answers; it is part of the run's name.
- **Registration:** `docs/rounds/s3-registration.md`, committed before S3.2's held-out runs. It fixed the rules and the nine predictions in advance.
- **Mutation test:** a test that breaks the code on purpose and checks that the other tests notice.
- **Shallow checkout:** a copy of the repository with only the latest commit and no history; CI uses one by default.
